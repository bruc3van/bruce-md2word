## 复现

先运行 `npm ci`、`npm run build`，再导出样例（默认输出目录为 `output/`）：

```powershell
node lib/cli.js fixtures/分页编号与脚注.md --strict
node lib/cli.js fixtures/长文档排版验收.md --strict
node lib/cli.js fixtures/技术文档排版验收.md --strict

./scripts/word-acceptance.ps1 -InputFile output/长文档排版验收.docx -Reader Word
./scripts/word-acceptance.ps1 -InputFile output/长文档排版验收.docx -Reader WPS
```

其他两个样例同样分别运行 Word/WPS。CLI 遇到同名文件会添加后缀，始终使用本轮实际返回的路径。

脚本需要本机安装对应阅读器；只修改唯一命名的验收副本，不覆盖源 DOCX。输出目录 `output/word-acceptance/` 包含带阅读器名称和时间戳的 DOCX、PDF、JSON。JSON 记录阅读器版本、页数、章节方向、实际列表编号和字段更新结果。保留这些文件作为本轮证据，再渲染 PDF 检查表格跨页、题注和页眉页脚。

脚本执行两轮域更新以解析前向引用。自动更新成功不能单独证明版面正确，仍需页面检查；不要只检查 XML，也不要把 LibreOffice 结果当作 Word/WPS 结果。
